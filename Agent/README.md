# Агент рабочего узла

Реализация **плана №1** для лабораторной работы «Распределённая система
обнаружения и загрузки видеоматериалов».

Агент — единственный компонент, который знает целевой сайт. Он арендует у
координатора блок числовых идентификаторов, проверяет каждый из них, извлекает
разрешённые метаданные, скачивает доступный файл, сохраняет его в том и
отчитывается о прогрессе.

Пакет работает на стандартной библиотеке Python 3.10+ — внешних зависимостей нет.

В составе стенда запускать агента вручную не нужно: координатор сам ставит его на серверы по SSH,
см. [README в корне репозитория](../README.md). Команды ниже нужны для работы с агентом отдельно.

## Состав

```
Agent/
├── agent/
│   ├── adapter.py        # знание о сайте: URL, классификация, метаданные
│   ├── cli.py            # run / check-config / doctor / version
│   ├── config.py         # загрузка и проверка конфигурации
│   ├── coordinator.py    # клиент API координатора, повторные попытки
│   ├── downloader.py     # загрузка, Range, контрольная сумма
│   ├── http_client.py    # пул соединений, тайм-ауты, ограничения
│   ├── journal.py        # состояние и очередь недоставленных подтверждений
│   ├── logging_setup.py  # JSON-журнал с полями из ТЗ
│   ├── ratelimit.py      # токен-ведро и адаптивное снижение частоты
│   ├── scheduler.py      # рабочий цикл: блок → проверки → прогресс → complete
│   ├── storage.py        # раскладка {storage}/{prefix}/{id}/
│   └── telemetry.py      # метрики cgroup, диска, сети
├── config/               # примеры конфигурации (YAML)
├── tests/                # unit, контрактные и сквозной тесты + мок-сервисы
├── tools/demo.py         # демонстрация без реального сайта
├── Dockerfile
└── docker-compose.yml    # три контейнера-агента с разными лимитами
```

## Быстрая проверка без реального сайта

```bash
python tools/demo.py
```

Скрипт поднимает локальный «сайт» и заглушку координатора, прогоняет один блок
идентификаторов и печатает таблицу статусов, список скачанных файлов и
контрольные суммы. Это тот же путь, которым пойдёт настоящий агент, — только
вместо `kinescope.io` отвечает мок.

## Тесты

```bash
python -m unittest discover -s tests -t .
```

Покрыто: разбор конфигурации и YAML-подмножества, классификация ответов
(200/404/401/403/429/5xx/тайм-аут), извлечение метаданных, загрузка с
продолжением по Range и без него, проверка размера и контрольной суммы,
повторные попытки и outbox координатора, сквозной прогон блока с проверкой
файлов и статусов.

## Запуск

```bash
cp config/agent.example.yaml config/agent.yaml
export AGENT_TOKEN=...                 # токен агента
python -m agent check-config -c config/agent.yaml
python -m agent doctor -c config/agent.yaml
python -m agent run -c config/agent.yaml
```

`run --once` обрабатывает один блок и выходит — удобно для отладки.
При установке через `pip install -e .` появляется команда `agentctl`.

## Конфигурация

| Ключ | Смысл |
|---|---|
| `agent.name` | имя узла в интерфейсе координатора |
| `agent.threads` | сколько идентификаторов проверять параллельно |
| `agent.storage_path` | каталог хранения (том контейнера) |
| `agent.min_free_space_gb` | порог, ниже которого новые загрузки не начинаются |
| `coordinator.base_url` / `token` | адрес API и токен агента |
| `coordinator.heartbeat_interval` / `lease_ttl` | интервалы; аренда не короче двух heartbeat |
| `limits.rps` | локальный предохранитель частоты запросов |
| `limits.check_concurrency` / `download_concurrency` | потолки параллельности |
| `retry.*` | повторы: число попыток, базовая задержка, потолок, джиттер |
| `site_adapter.page_url_template` | шаблон адреса страницы, обязан содержать `{id}` |
| `site_adapter.found_markers` / `missing_markers` | признаки наличия и отсутствия материала |
| `site_adapter.download.policy` | `public_only` — скачивать публичное, `never` — только собирать метаданные |
| `site_adapter.download.max_file_size_bytes` | предел размера файла |

Секреты в файл не пишутся: `token: ${AGENT_TOKEN}` подставляется из окружения.
Переопределения через окружение: `AGENT_NAME`, `AGENT_THREADS`,
`AGENT_STORAGE_PATH`, `AGENT_COORDINATOR_URL`, `AGENT_TOKEN`, `AGENT_RPS`,
`AGENT_SITE_TEMPLATE`, `AGENT_LOG_LEVEL`.

## Docker

```bash
docker compose up -d --build
docker compose ps
docker stop <container-worker-02>     # имитация отказа узла
docker compose logs -f worker-01
```

Каждый сервис — отдельный контейнер с своим томом и своими лимитами
(1 CPU/512 МБ, 2 CPU/1 ГБ, 0.5 CPU/256 МБ): это заменяет три разные машины.
Корневая файловая система только для чтения, запись — лишь в том с данными.

## Как настроить под реальный сайт

В коде нет ни одного селектора конкретной страницы — всё в конфигурации:

1. `page_url_template` — адрес страницы по идентификатору.
2. `missing_markers` — фразы, которыми сайт сообщает «материала нет».
   По умолчанию там русские и английские варианты.
3. `found_markers` — признаки страницы с материалом, если ссылка на файл
   не извлекается автоматически.
4. `player_config_path` — путь к полю в JSON плеера (например, `video.contentUrl`),
   если ссылка лежит в известном месте.
5. `download.policy` и `max_file_size_bytes` — что разрешено скачивать.

Адаптер сам ищет ссылки на файлы в разметке и в JSON-блоках (`og:title`,
`application/ld+json`, поля `contentUrl`, `videoUrl`, `src`), поэтому часто
достаточно только шаблона адреса. Если разметка изменилась — правится
конфигурация, а не платформа.

## Принятые решения

* **Знание о сайте — только в адаптере.** Остальные модули работают с
  нормализованным результатом (статус, метаданные, ссылка).
* **At least once.** Блок закрывается с `next_id`; повторная обработка
  допустима, поэтому запись файла и метаданных идемпотентна.
* **Ничего не теряется при перезапуске.** Частичный файл остаётся в томе и
  продолжается по Range; подтверждения блока, которые не удалось отправить,
  лежат в outbox и досылаются позже.
* **Общий IP — общий лимит.** Агент строго соблюдает `rps_share`, выданный
  координатором в аренде, а локальный `limits.rps` — лишь предохранитель.
* **Отказы не обходятся.** 401/403 фиксируются как `forbidden` без повторов
  и без попыток обойти ограничение.

## Известные ограничения

* HLS-плейлисты не собираются: скачивается только прямой файл (`.mp4` и подобные).
* Прокси и клиентские сертификаты не поддерживаются.
* Сетевые метрики читаются из `/proc/net/dev`, поэтому на Windows равны `null`.
* Один агент обрабатывает один блок за раз: параллелизм внутри блока, а не
  между блоками.
* Разметка реального сайта не проверялась вживую: адаптер покрыт мок-сервисом
  и фикстурами, при первом запуске на реальном сайте может понадобиться
  дополнить `missing_markers` или `player_config_path`.
