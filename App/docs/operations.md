# Установка, обновление, масштабирование

## Установка на чистую машину

Требуются Docker с Compose 2.24.4 и новее, git, bash, openssl и ssh-keygen. На Windows всё, кроме
Docker, входит в Git for Windows, команды выполняйте в Git Bash. Минимум для стенда:
4 vCPU и 8 ГБ памяти.

```bash
git clone https://github.com/Andraboba/Ushastiy.git
```

```bash
cd Ushastiy/App
```

```bash
bash scripts/init-env.sh
```

```bash
docker compose up -d --build
```

`init-env.sh` создаёт случайные секреты в `secrets/` и сертификаты TLS в `deploy/tls/`. Обе папки в
git не попадают. Существующие файлы скрипт не перезаписывает, запускать его можно повторно.

Проверка: `docker compose ps` показывает `healthy` у `db`, `redis`, `api`, `web`, затем откройте
https://localhost:8443 и войдите как `admin` с паролем из `secrets/coord_admin_password`.

## Настройки

Переменные окружения с приставкой `COORD_`, полный список в `src/coordinator/config.py`. Основные:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `COORD_GLOBAL_RPS_LIMIT` | 20, на стенде 3000 | Общий лимит запросов. **Для настоящего сайта обязательно снизьте** в `.env` |
| `COORD_HEARTBEAT_INTERVAL` | 5 | Интервал heartbeat, секунды |
| `COORD_LEASE_TTL` | 60 | Срок аренды блока, секунды |
| `COORD_WORKER_OFFLINE_AFTER` | 11 | Через сколько секунд без heartbeat узел недоступен |
| `COORD_MAX_CHUNK_ATTEMPTS` | 5 | После скольких попыток блок становится `failed` |
| `COORD_DEFAULT_MIN_FREE_SPACE_GB` | 1 | Резерв места, ниже которого узел не получает блоки |
| `COORD_RUNNER_IMAGES` | `coord/agent-stub:*,lab/agent:*` | Allowlist образов |
| `COORD_TERMINAL_IDLE_SECONDS` | 300 | Автозавершение терминала без ввода |
| `COORD_API_WORKERS`, `COORD_API_CPUS` | 1, 1.0 | Процессы `api` и лимит CPU для них, только в `.env` для compose |

## Обновление платформы

```bash
git pull
```

```bash
docker compose up -d --build
```

Миграции применятся сами. Работающие агенты переживут перезапуск `api`: подтверждённое не теряется,
неотправленное они повторят. Перед обновлением схемы сделайте резервную копию:

```bash
docker compose exec -T db pg_dump -U coord coord > backup.sql
```

## Серверы и агенты по SSH

`worker-01..03` из `compose.yaml` изображают отдельные серверы: образ `coord/ssh-server:dev` содержит только
sshd и Python, агента в нём нет. Список лежит в `deploy/servers.json`, при запуске он попадает в базу.
Дальше работает диспетчер: заходит на сервер по SSH, выкладывает агента в `~/agent/releases/<выпуск>`,
пишет настройки в `~/agent/agent.env` с правами 600 и запускает. Упавшего агента он поднимает сам.

Какой агент ставить на серверы, определяет `COORD_AGENT_KIND` в `.env`, по умолчанию настоящий:

| Значение | Что ставится |
|---|---|
| `real` | Настоящий агент из `../Agent`, он работает с тестовым сайтом `site` |
| `stub` | Заглушка из `stub/`, понимает управляющий файл для имитации отказов |

```bash
COORD_AGENT_KIND=stub docker compose up -d --build
```

Настройка действует на серверы при первой установке. Уже установленному агенту вид меняют на странице
узла: «Установить настоящего агента» или «Установить заглушку».

Ключи:

- Закрытый ключ лежит в `secrets/ssh_client_key`, он есть только у `runner`. Открытый `secrets/ssh_client_key_pub`
  попадает на серверы. Оба создаёт `init-env.sh`.
- Запомненные ключи серверов хранятся в томе `runner-state`. Сервер, пересозданный с тем же томом ключей,
  остаётся тем же сервером. Если он заменён начисто, вход будет отклонён с кодом `host_key_changed`:
  проверьте замену и нажмите на странице узла «Сервер заменён: забыть его ключ».
- `COORD_SSH_ALLOWED_HOSTS` ограничивает, куда runner вообще может подключиться. По умолчанию `worker-*,lab-*`.

**Настоящая машина.** Добавьте её адрес в `COORD_SSH_ALLOWED_HOSTS`. На машине заведите пользователя без
прав root, положите ему открытый ключ в `~/.ssh/authorized_keys`, установите `python3`. Агенту нужен доступ
к координатору, поэтому задайте `COORD_AGENT_COORDINATOR_URL` и разложите CA стенда или выпустите
сертификат от доверенного центра. Затем «Узлы» → «Добавить сервер» без отметки «Создать контейнер».
**Перед работой с настоящим сайтом снизьте `COORD_GLOBAL_RPS_LIMIT`.**

Прежний вариант, в котором агент сам является контейнером и работает restart policy:

```bash
docker compose -f compose.yaml -f deploy/compose.docker-mode.yaml up -d --build
```

## Масштабирование

**Из интерфейса** (нужна роль administrator): «Узлы» → «Добавить сервер». С отметкой «Создать контейнер»
runner поднимет новый контейнер-сервер, без неё укажите адрес готового сервера. Токен выпускается
автоматически и попадает только в `agent.env` на сервере.

**Через compose:** добавьте сервис `worker-0N` по образцу имеющихся и строку в `deploy/servers.json`, затем:

```bash
docker compose up -d --build
```

Контейнеры, созданные из интерфейса, не входят в проект compose, и `docker compose down` их не останавливает.
Перед удалением стенда уберите их сами: контейнер `lab-<имя>` и тома `lab-videos-<имя>`, `lab-sshkeys-<имя>`.

Добавлять и убирать узлы можно не останавливая задание. Узел начинает получать блоки сразу после
регистрации, его доля общего лимита рассчитывается на следующем проходе диспетчера.

Узкое место при росте числа агентов — один процесс `api` с лимитом 1 CPU. Начиная примерно с 30 агентов
задайте `COORD_API_WORKERS` и `COORD_API_CPUS` в `.env`, цифры в [отчёте о нагрузке](load-report.md).

## Ротация секретов

**Токен агента без остановки узла.** «Пользователи» → «Токены агентов» → «Выпустить токен». Передайте
токен агенту, перезапустите его и отзовите старый. Пока оба действуют, узел работает.

**Токен runner-а.** Запишите новое значение в `secrets/coord_runner_token`, затем:

```bash
docker compose up -d --force-recreate api dispatcher runner
```

**Сертификаты TLS.** Сессии пользователей и работа узлов продолжатся после перезапуска:

```bash
bash scripts/init-env.sh --renew-tls
```

```bash
docker compose up -d --force-recreate
```

**Пароль пользователя** меняется в разделе «Пользователи». Все сессии этого пользователя при этом
завершаются. Файл `secrets/coord_admin_password` используется только при самом первом запуске.

## Резервное копирование

Состояние системы целиком в базе: `pg_dump`, как выше. Файлы лежат в томах `videos-*` на узлах и
копируются отдельно.

## Режим разработки без TLS

Интерфейс на http://localhost:8080 и API напрямую на http://localhost:8000. Пароли и токены при этом
идут открытым текстом, для настоящей работы режим не подходит.

```bash
docker compose -f compose.yaml -f deploy/compose.dev.yaml up -d --build
```
