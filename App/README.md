# Платформа: координатор, API и веб-интерфейс

Центральная часть лабораторной работы «Распределённая система обнаружения и загрузки
видеоматериалов». Управляет заданиями, раздаёт агентам небольшие арендуемые блоки идентификаторов,
хранит результаты и показывает всё это оператору. Сам агент лежит в соседнем каталоге `../Agent`.

## Быстрый старт

Запуск с нуля на новом устройстве, требования и решение проблем описаны в
[README в корне репозитория](../README.md). Коротко, из этого каталога:

```bash
bash scripts/init-env.sh
```

```bash
docker compose up -d --build
```

Откройте https://localhost:8443. Сертификат подписан собственным CA стенда, файл
`deploy/tls/ca.crt`: добавьте его в доверенные браузера или подтвердите исключение.
Вход: логин `admin`, пароль в файле `secrets/coord_admin_password`.

Поднимутся `db`, `redis`, `api`, `dispatcher`, `runner`, `web`, тестовый сайт `site` и три контейнера
`worker-01..03`. Они изображают отдельные серверы с SSH: агента в образе нет, координатор сам входит на
них по ключу, ставит агента и запускает его. Арендовать машины не нужно, а настоящий сервер подключается
так же. Создайте задание на странице «Задания» и запустите его.

## Что где

| Каталог | Что внутри |

| `src/coordinator/domain` | Чистая логика: диапазоны, статусы, балансировка, лимит запросов, предупреждения |
| `src/coordinator/storage` | Модели и работа с базой, Redis |

| `src/coordinator/api` | HTTP API и шлюз терминала |
| `src/coordinator/runner` | Единственный сервис с доступом к Docker API и закрытому ключу SSH |
| `src/coordinator/provisioning.py` | Установка агентов и сверка серверов с желаемым состоянием |
| `stub` | Эталонная заглушка агента |
| `web` | Интерфейс на React, nginx |
| `migrations` | Миграции Alembic |
| `deploy` | Dockerfile, образ сервера с SSH, список серверов, Prometheus, Grafana, режимы compose |
| `scripts` | CI, сценарии отказов, нагрузочный тест, чек-лист приёмки |
| `docs` | Документация |

## Проверки

Полная проверка, как в CI: сборка образов, линтер, миграции на чистой базе, все тесты.
Успех — последняя строка `CI OK`.

```bash
bash scripts/ci.sh
```

Быстрый цикл при разработке, без пересборки образов, аргументы уходят в pytest:

```bash
bash scripts/dev-test.sh tests/test_leases.py
```

Сценарии отказов на поднятом стенде (`docker kill`, обрыв сети, OOM, заполнение диска и другие):

```bash
python scripts/chaos.py
```

Чек-лист «подключили агента — всё работает», вид агента определяется по стенду:

```bash
python scripts/acceptance.py
```

Нагрузочный тест, результат в `docs/load-results.md`:

```bash
bash scripts/loadtest.sh
```

## Мониторинг

Prometheus и Grafana запускаются отдельно, на портах только для локальных подключений:

```bash
docker compose --profile monitoring up -d
```

Grafana: http://127.0.0.1:3000, логин `admin`, тот же пароль. Дашборд «Координатор» подключён
автоматически. Те же предупреждения видны на главной панели и без Prometheus.
