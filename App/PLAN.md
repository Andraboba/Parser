# План реализации платформы и текущий прогресс

Источник: `ПЛАН_2_Платформа.docx` (этапы Э0–Э13). Работа разбита на tracer-bullet тикеты по skill
[`to-tickets`](https://github.com/mattpocock/skills/tree/main/skills/engineering/to-tickets) (Matt Pocock):
каждый тикет проходит через все слои (схема → API → заглушка агента → React-интерфейс → тесты)
и проверяется сам по себе. Трекер не ведём, статусы — в этом файле.

**Стек:** Python 3.13, FastAPI, SQLAlchemy 2 (async, psycopg 3), Alembic, PostgreSQL 17, Redis 7.
Фронт — React (Vite + TypeScript). Python-пакет называется `coordinator`
(имя `platform` конфликтует со стандартной библиотекой).

**Git:** корень репозитория — родительская папка (`Ushastiy/`), remote `origin` на GitHub.
Коммиты делаются вручную или по явной просьбе. Workflow лежит в `.github/workflows/platform-ci.yml`.

## Где остановился (05.11.2026)

Все тикеты 01–21 готовы, сверх них сделан режим SSH: контейнеры `worker-01..03` изображают серверы, координатор
сам ставит на них агентов по SSH, поэтому арендовать машины не нужно. Описание в `docs/operations.md`.
`bash scripts/ci.sh` заканчивается строкой `CI OK`, стенд поднимается через
`bash scripts/init-env.sh && docker compose up -d --build`, интерфейс: https://localhost:8443.
**Изменения не закоммичены:** коммит делается вручную или по явной просьбе. Вся документация в `README.md` и `docs/`.

Как проверять:
- `scripts/dev-test.sh [аргументы pytest]` — быстрый цикл без пересборки образов;
- `scripts/ci.sh` — полная проверка перед сдачей;
- `python scripts/chaos.py [сценарий]` — 12 сценариев отказов на стенде с `COORD_AGENT_KIND=stub`;
- `python scripts/acceptance.py` — чек-лист раздела 16, вид агента определяется по стенду;
- `bash scripts/loadtest.sh` — нагрузка, отчёт в `docs/load-report.md`.

Принятые решения, которые стоит помнить:
- `worker_id` — целое число. В примере плана была строка `"w-01"`; окончательно контракт
  фиксируется в тикете 03.
- `complete` требует `next_id == range_end + 1`. Частичный прогресс пойдёт через `progress`
  в тикете 06.
- `complete_chunk` блокирует строку задания (`FOR UPDATE`), иначе два параллельных закрытия
  не увидят друг друга и задание не перейдёт в `completed`.
- Повтор идентификатора внутри одного `complete` не ошибка: сохраняется последний результат.
- Узел регистрируется по имени (upsert), а не по адресу: пересозданный контейнер сохраняет id.
- Заглушка берёт лимиты из cgroup, поэтому в UI видно то, что реально задано в `compose.yaml`.

- Блоки создаются по мере работы: в `jobs.next_chunk_start` курсор, огромный и открытый диапазоны
  устроены одинаково, задание создаётся мгновенно.
- `complete` с неполным `next_id` возвращает блок в очередь с контрольной точкой.
- Поздний `complete` или `progress` принимается, если блок никому не передан.
- Heartbeat сверяет блоки с `active_chunks`: иначе потерянный блок продлевался бы вечно.
- `Idempotency-Key` хранится вместе с номером попытки блока: настоящий агент шлёт `fail-{id}`,
  а один блок может отказать несколько раз.
- После простоя базы или диспетчера — «амнистия» (`grant_amnesty`): один срок на восстановление.
- Заглушка падает по команде через управляющий файл: `docker kill` Docker считает ручной
  остановкой, и политика перезапуска такой контейнер не поднимает.

- Настоящему агенту добавлены указания из ответа heartbeat: доля лимита, потоки, отмена блока
  (`Agent/agent/scheduler.py`, тест `Agent/tests/test_instructions.py`).
- Секреты файлами в `secrets/`, не в окружении контейнера. Сертификаты в `deploy/tls/`, с расширениями X.509:
  Python 3.13 и новее проверяет цепочку строго.
- Порт `api` наружу не открыт, агенты и интерфейс идут через nginx и TLS. Режим без TLS: `deploy/compose.dev.yaml`.

Известные ограничения и что не сделано: `docs/limitations.md`.

### Особенности окружения (Windows)
- Перед запуском CI и стенда нужно запустить Docker Desktop.
- Локально стоит только Python 3.14 (`python`), а проект требует 3.13, локального `.venv` нет.
  Линтер и тесты запускаются в Docker через `scripts/ci.sh`.
- Фронт можно собирать локально: `npm ci` и `npm run build` в `web/` (Node 26).
- Успех `scripts/ci.sh` — это строка `CI OK`. С `| tail` код возврата будет от `tail`,
  и упавший прогон выглядит успешным.
